# 模块5 路线A 构效关系搜索融合 · 研究发现（findings）

## 技术调研

### 前沿参考：Automat（arXiv:2605.14671, 2026）
- **内容**：autoresearch 框架，LLM 编码代理自动设计成分描述符（composition-only descriptors），随机森林工作流评估
- **关键机制**：
  - 两级验证协议：局部接受/拒绝用训练集内层 CV MAE；held-out 验证集仅监控泛化与选最终 checkpoint
  - 每次迭代记录 rationale + 实现（idea.md/idea.py），累积可审计的发现轨迹
  - 化学可解释：产物是描述符族而非黑箱，可直接解释构效关系
- **启示**：LLM 引导搜索可超越 Magpie/分数成分基线，但需控制描述符冗余与搜索复杂度

### 前沿参考：LLM 属性预测置信度（arXiv:2605.03515, 2026）
- **内容**：微调 Llama 1B/8B 预测形成能/带隙，评估五种输入表示（成分/晶格摘要/局域环境/全文/CIF）
- **关键结论**：
  - 含空间群信息的晶格摘要在两规模上均优于纯成分输入（对称性是稳健特征）
  - 微调模型 token 级 mean NLL 与预测误差负相关，可作无需额外训练的置信度指标
- **启示**：路线 A 候选评估可引入置信度（LLM NLL 或代理模型不确定性），提升筛选可靠性

### 搜索 × LLM 融合模式（赛题创新点）
- **三角色设计**：LLM 生成器（提议候选+理由）→ 评估器（可行性/科学合理性打分）→ 剪枝器（决定保留/淘汰）
- **混合搜索**：GA 负责全局探索、MCTS 负责序列决策、贝叶斯优化负责连续参数、符号回归负责显式公式
- **LLM 不替代搜索**，而是引导搜索方向（种群初始化、变异算子、剪枝阈值），保留可审计性与可复现性

## 重要发现

### 发现 1：融合深度 = 创新性得分
- **内容**：赛题明确要求「搜索方法与 LLM 深度融合而非仅生成搜索代码」
- **影响**：LLM 必须参与生成/评估/剪枝环节，而非只当代码生成器
- **建议**：消融实验（有/无 LLM 引导）量化增益，写入复赛报告

### 发现 2：可解释性支撑科学意义
- **内容**：评委看的是「是否揭示构效关系」，而非黑箱命中
- **影响**：输出须是显式描述符/关系式，附化学依据
- **建议**：优先符号回归与可解释描述符路线，参考 Automat 的 rationale 记录

### 发现 3：两级验证防过拟合
- **内容**：用验证集做局部决策会污染泛化评估
- **影响**：搜索过程须隔离「决策数据」与「评测数据」
- **建议**：复用 Automat 的 inner-CV 决策 + held-out 评测两级协议
