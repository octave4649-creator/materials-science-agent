# 模块4 调研报告生成 Agent · 研究发现（findings）

## 技术调研

### 报告评测维度（赛题）
- **结构化程度**：章节完整、层级规范、信息密度合理
- **可读性**：摘要清晰、术语一致、图表辅助、无冗余
- **文献溯源完整性**：每个结论可回溯到文献/证据链

### 结构化报告最佳实践
- 摘要先行（300 字内：问题、方法、发现、意义）
- 章节编号 + 统一层级（H1/H2/H3 不跳级）
- 数据密集型内容用表格/矩阵，避免长段落
- Gap 清单用「描述 + 证据 + 新颖性 + 可操作性」四列表格
- 参考文献与证据链附录分离，正文用 [n] 编号引用

## 重要发现

### 发现 1：报告是评分直接载体
- **内容**：调研报告是基本任务三大产出之一，直接进评测
- **影响**：报告质量与检索/抽取/Gap 同等重要，不可轻视
- **建议**：预留独立开发时间，模板先行

### 发现 2：LLM 润色须受证据约束
- **内容**：整篇 LLM 生成报告容易编造文献/数值
- **影响**：必须「模板 + 数据填充 + 局部润色」三明治结构
- **建议**：润色阶段给 LLM 传入证据链上下文，禁止新增未引用的数值

### 发现 3：报告可复用为提交物
- **内容**：初赛 4 页方案、复赛实验报告、决赛一页纸
- **影响**：一份调研报告可裁剪复用，减少重复劳动
- **建议**：模板设计时预留「裁剪开关」（隐藏章节）
