# 基础任务·文献调研 Agent

## 1. 任务定位

基本任务为**必做项**，占材料方向评估 50%。构建一个能够自主进行材料科学文献调研的智能体（Agent），具备四项能力：文献检索与筛选、知识抽取、Research Gap 识别、调研报告生成。产出物将作为三条进阶路线的输入基础。

## 2. Agent 架构设计

### 2.1 架构选型

| 架构 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| 单 Agent（顺序流水线） | 实现简单、流程可控 | 单点能力受限、难以并行 | 初赛快速原型 |
| 多 Agent（角色分工） | 能力解耦、可并行、容错好 | 协调复杂、token 消耗高 | 复赛/决赛完整方案 |

### 2.2 推荐架构：检索-抽取-分析-报告四阶段流水线

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ 检索Agent│ → │ 抽取Agent│ → │ 分析Agent│ → │ 报告Agent│
└─────────┘   └─────────┘   └─────────┘   └─────────┘
  检索筛选      知识抽取      Gap识别       报告生成
```

- **检索 Agent**：负责文献检索与筛选（Sciverse agentic-search / meta-search）
- **抽取 Agent**：负责结构化知识抽取（成分/结构/性能/方法/条件）
- **分析 Agent**：负责 Research Gap 识别与交叉验证
- **报告 Agent**：负责结构化调研报告生成

### 2.3 Sciverse MCP 接入设计

- 通过 `sciverse-mcp-server` 将 Sciverse 六类 API 暴露为 Agent 工具
- 每次调用记录构成可审计证据链：查询词、时间戳、返回片段 ID、来源 DOI
- 工具规划（Tool Planning）：检索 Agent 根据研究问题拆分子任务，动态选择 API 组合

### 2.4 证据链审计设计

每个结论必须关联证据链，输出格式：

```
结论陈述
├─ 证据片段 1（来源：agentic-search 返回，DOI: 10.xxxx/xxxx，页码 p.5）
├─ 证据片段 2（来源：content 全文核验，DOI: 10.xxxx/xxxx，段落 #sec-3）
└─ 数据库验证（来源：Materials Project，material_id: mp-149）
```

## 3. 知识抽取方案

### 3.1 抽取目标（结构化信息）

| 类别 | 抽取内容 | 示例 |
|------|---------|------|
| 材料成分 | 化学式、元素组成、掺杂 | LiFePO₄、NMC811 |
| 晶体结构 | 空间群、晶格参数、相 | Fm-3m、a=4.05 Å |
| 材料性能 | 带隙、电导率、强度、催化活性 | 3.4 eV、10⁻³ S/cm |
| 模拟方法 | 计算方法、软件、参数 | DFT-PBE、VASP、500 eV 截断 |
| 合成条件 | 前驱体、温度、时间、气氛 | 800°C 氩气 4h |

### 3.2 LLM 结构化输出 Schema

```json
{
  "material": {
    "formula": "string",
    "composition": "string",
    "structure": {"space_group": "string", "lattice": "string", "phase": "string"}
  },
  "properties": [
    {"name": "string", "value": "number", "unit": "string", "condition": "string"}
  ],
  "methods": [
    {"type": "DFT|MD|ML|EXPERIMENT", "software": "string", "key_params": "string"}
  ],
  "synthesis": {
    "precursors": "string", "temperature": "string",
    "atmosphere": "string", "duration": "string"
  },
  "source": {"doi": "string", "page": "string", "paragraph": "string"}
}
```

### 3.3 抽取策略

- **LLM + 结构化提示词**：用 schema 约束 LLM 输出，JSON 化存储
- **MinerU 联动**：先用 MinerU 将 PDF 解析为 Markdown，再交给 LLM 抽取，提高非结构化文本处理质量
- **多轮校验**：抽取结果回查原文片段，防止幻觉
- **去重合并**：多篇文献中的同一材料体系进行归一化（别名、同构异名）

### 3.4 知识库存储

- 每条抽取记录 = 一个材料知识三元组/四元组（成分-结构-性能-条件）+ 证据链接
- 推荐存储格式：JSON/Parquet 文件 + 向量化索引（供语义检索）

## 4. Research Gap 识别

### 4.1 Gap 类型

| 类型 | 定义 | 示例 |
|------|------|------|
| 未探索方向 | 文献中未被充分研究的成分/性能区间 | 某掺杂体系在高压下的稳定性 |
| 矛盾结论 | 不同文献报道互相冲突的结果 | 同一材料带隙报道差异大 |
| 缺失知识连接 | 两个领域/性质之间缺少关联研究 | 结构与催化活性缺乏系统关联 |
| 方法空白 | 缺少高效计算方法/实验手段 | 尚无 ML 势函数覆盖某体系 |

### 4.2 识别方法

1. **覆盖率分析**：统计某材料体系的研究分布（成分×结构×性能矩阵），寻找空白格
2. **矛盾检测**：对同一体系的多条抽取记录做数值对比，标记冲突
3. **连接发现**：用知识图谱/共现分析发现两个性质域之间的弱关联
4. **LLM 推理**：基于抽取知识库让 LLM 提出未被探索的方向，再由证据链验证
5. **新颖性评估**：与 Sciverse 检索结果比对，确认 Gap 尚未被文献覆盖

### 4.3 评估要点对照

- **准确率**：Gap 是否真实存在（证据支撑）
- **新颖性**：Gap 是否超出已有研究边界
- **可操作性**：Gap 是否能转化为可执行的研究路线（对应进阶路线）

## 5. 调研报告生成

### 5.1 报告结构

```
# 文献调研报告
## 1. 研究问题与范围
## 2. 检索策略与数据来源（含检索记录/时间戳）
## 3. 知识抽取结果（结构化数据表）
## 4. Research Gap 清单
    每个 Gap 包含：描述 / 证据链 / 文献交叉引用 / 潜在研究方向
## 5. 文献综述（按主题组织）
## 6. 结论与建议
## 附录：文献清单（DOI、标题、来源）
```

### 5.2 文献交叉引用

- 每个 Gap/结论引用至少 2-3 篇支撑文献
- 引用格式统一：作者、年份、标题、DOI、来源（Sciverse 记录 ID）
- 区分「已有共识」「部分争议」「未被研究」

### 5.3 可读性控制

- 结构化小标题 + 表格化呈现数据
- 证据链可视化（引用标注在结论旁）
- 避免纯文字长段落，优先表格/列表

## 6. 评估要点自检清单

- [ ] Research Gap 识别是否准确且新颖（每条有证据链）
- [ ] 文献溯源是否完整可信（DOI、页码、检索记录）
- [ ] 报告是否结构化且可读
- [ ] 知识抽取是否覆盖成分/结构/性能/方法/条件五类信息
- [ ] 证据链是否可审计（每个结论可回溯）
